# Vendored upstream sources

A working copy of pony-lsp and the `pony_compiler` bridge it uses, taken
unmodified from ponyc so that changes can be made and tested here and
applied upstream as one change rather than a series of them.

## Provenance

| | |
|---|---|
| Repository | `ponylang/ponyc` |
| Revision | `c67928519c2953c151812694d0521cbd88d2a24b` |
| Date | 2026-08-26 |
| Subject | Update release notes for PR #5872 |
| Working tree | clean at copy time |

Paths mirror the upstream layout, so `upstream/tools/pony-lsp/...` is
`tools/pony-lsp/...` in ponyc. Exactly the files `git ls-files` reported for
those two directories were copied, and nothing else.

## Producing the patch

The commit that introduced this directory contains the pristine copy and
nothing else, so everything since is the change:

    git diff <that commit>..HEAD -- upstream/

Applied at the root of a ponyc checkout with `git apply -p2`, or by
rebasing onto the revision above if it has moved on.

## What a trial application showed

The patch was applied to a ponyc checkout once, built, and tested, then
reverted. Three things came out of it that the patch now accounts for, and
one it does not.

**ponyc's root `CMakeLists.txt` needs a search path.** The `pony-lsp-tests`
target is defined there, not in `tools/pony-lsp/CMakeLists.txt`, and it needs
`${CMAKE_SOURCE_DIR}/tools/lib/ponylang` on its `PATHS` or the test binary
cannot find the new packages. That file is not vendored here, so the change
is recorded rather than carried:

    add_pony_binary(pony-lsp-tests
        NAME pony-lsp-tests
        SOURCE ${CMAKE_SOURCE_DIR}/tools/pony-lsp/test
        PATHS ${CMAKE_SOURCE_DIR}/tools/lib/ponylang/pony_compiler \
              ${CMAKE_SOURCE_DIR}/tools/lib/ponylang
        WATCH ${CMAKE_SOURCE_DIR}/tools/pony-lsp)

**`AGENTS.md`'s lint command needs the same path.** It documents

    PONYPATH=../../tools/lib/ponylang/pony_compiler ./pony-lint ../../tools/pony-lsp/

which now fails to load `pony_analysis`. It wants
`pony_compiler:../../tools/lib/ponylang`.

**ponyc lints its own tools, and this code did not pass.** Running `pony-lint`
over the three trees found exhaustive matches without the annotation, single
line docstrings, blank lines between fields, multi-line call formatting, a
file named for the wrong principal type, and `Ffi` where the project spells it
`FFI`. All of that is fixed here now, and `pony-lint` should be run before any
future attempt rather than after.

**The full suite passed**: 15 of 15 ctest tests, including the compiler suite,
stdlib in debug and release, full-programs, examples, and all four tool test
binaries.

## One file is not upstream's to receive

`tools/pony-lsp/version.pony` is generated by CMake from `version.pony.in`
and is git-ignored in ponyc. It is copied here because the code does not
build without it, and it is ignored here too, so it never reaches a patch.
